# shortmaker-deadman

Замечает, когда сервер `shortmaker` перестаёт подавать признаки жизни, и пишет об этом
в Telegram.

Ничто, работающее на самом сервере, не может сообщить о его смерти: мёртвый процесс
не отправляет ничего, а тишина неотличима от здоровья. Поэтому сервер раз в минуту
записывает текущее время в секретный gist, а этот репозиторий раз в 15 минут смотрит,
насколько это время устарело. Перестало обновляться — отключили свет, пропала сеть или
зависла машина. Все три случая заслуживают одного и того же звонка.

Живёт здесь, а не на сервисе мониторинга, потому что каждому из них нужна регистрация
с подтверждением по почте, а письма не доходили. Задаче по сути нужен компьютер в другом
здании — workflow по расписанию им и является.

## Как устроено

```
сервер (/etc/shortmaker-watchdog.env)          GitHub
  watchdog.py раз в минуту                       gist: beat.txt = "<epoch> ok|fail"
        │  PATCH (токен со scope gist)                    │
        └────────────────────────────────────────────────▶│
                                                          │  читает раз в 15 мин
                                          .github/workflows/deadman.yml
                                                          │
                                              состояние сменилось?
                                                          │
                                                    Telegram ✉
```

`state.json` хранит последнее известное состояние, чтобы сообщение уходило один раз на
проблему, а не каждые 15 минут. Он же — доказательство активности репозитория: GitHub
отключает расписание там, где 60 дней не было коммитов, поэтому раз в три недели файл
переписывается даже когда ничего не менялось.

## Что нужно настроить

Секреты репозитория (Settings → Secrets and variables → Actions):

| Секрет | Что это |
|---|---|
| `GIST_ID` | идентификатор gist с сердцебиением |
| `GIST_TOKEN` | тот же токен со scope `gist`, что и на сервере. Без него запросы к GitHub идут анонимно, а анонимный лимит — 60 в час на адрес, общий у всех hosted-раннеров: сторож начинает слепнуть в случайные моменты |
| `ALERT_BOT_TOKEN` | токен телеграм-бота-сторожа (не продуктового) |
| `ALERT_CHAT_ID` | куда писать |

На сервере, в `/etc/shortmaker-watchdog.env`: `DEADMAN_GIST_ID` и `DEADMAN_GIST_TOKEN`
(токен со scope `gist` и больше ничем — украденная копия не дотянется до кода).

## Пороги

* сервер бьёт раз в минуту;
* проверка раз в 15 минут;
* тревога после **30 минут** тишины — окно переживает один пропущенный запуск плюс
  перезагрузку, иначе каждое обновление сервера поднимало бы ложный алярм.
